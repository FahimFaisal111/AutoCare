In Feature 1 (Multi-Tenancy), the database follows 3NF and EER specialization (user supertype with customer and mechanic subtypes sharing workshop_id foreign keys), allowing the Admin Dashboard to aggregate real-time, tenant-isolated metrics (customer counts, fleet vehicles, mechanics, appointments, and revenue) while enforcing @PreAuthorize security checks that reject unauthenticated mechanic registrations with 403 Forbidden. In Feature 5 (Conflict-Free Scheduling), bookings are serialized under ACID transactions using MySQL InnoDB pessimistic row locking (SELECT ... FOR UPDATE) and evaluated against a B-Tree indexed mathematical interval check (existing.start < new.end AND existing.end > new.start), which instantly throws a 409 Conflict on overlapping slots while permitting exact back-to-back appointments. Finally, in Feature 8 (Invoicing & Payments), marking an appointment as COMPLETED idempotently auto-provisions a single PENDING invoice with calculated parts and labor costs, guaranteed to never duplicate via a strict UNIQUE (appointment_id) 1:1 relational constraint, while role-based query filters ensure customers only view their own invoices, admins can query workshop totals and mark them as PAID, and unauthorized roles like mechanics are strictly denied access.
